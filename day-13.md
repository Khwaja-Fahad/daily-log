## Talk 1: Be careful using AI for PowerShell
- AI can write scripts that look correct but are wrong or unsafe, and it
  may invent commands that don't exist.
- The speaker also argued that not everything is public, so an AI may
  not know the full picture.
- My habit: **read it, understand it, test it in a safe lab** before
  running AI-written code on a real system.

## Talk 2: Testing how AI models can be tricked
- You can't see inside an AI model, so testers try many different
  inputs and watch how it responds. This is called adversarial testing.
- It is a growing area of security.
- Terms to look up: prompt injection, jailbreaking, AI red teaming.
- I only record the concept here, not ways to bypass any AI's rules.

## Talk 3: Backups
- Backups protect data from theft and destruction, so a ransomware
  attack or an accidental deletion does not end the business.
- **3-2-1 rule:** 3 copies of the data, on 2 types of storage, with
  1 copy offsite or offline.
- Attackers often try to delete or encrypt backups too, so one copy
  should be offline or immutable.
- Test restoring regularly. A backup that has never been restored may
  not work.
